# نظم، ناظم می‌خواهد

انیمیشن سه‌بعدی تعاملی که «مونتاژ یک موتر» را در کنار «شکل‌گیری سوراخ بینی جنین»
قرار می‌دهد تا پیام یکسانشان را نشان دهد: هر ساختار منظم، از یک نقشه شروع
می‌شود، قدم‌به‌قدم و به‌ترتیب ساخته می‌شود، و اگر فقط یک قطعه/ژن درست کار نکند،
کل نظم فرومی‌پاشد.

ساخته‌شده با (Vite) + (TypeScript) + (Three.js)، رندر (PBR) با محیط (HDRI)،
پساپردازش (bloom/DOF)، و فروپاشی فیزیکی واقعی با (cannon-es).

## اجرا

```bash
npm install
npm run dev
```

سپس آدرسی که (Vite) چاپ می‌کند (معمولاً `http://localhost:5173`) را در مرورگر
باز کنید. برای build نهایی:

```bash
npm run build
npm run preview
```

## ساختار کد

- `src/scene.ts` — رندرر، دوربین سینمایی/(OrbitControls)، نور و محیط (HDRI)، کف و پساپردازش
- `src/car.ts` — بارگذاری موتر، تفکیک قطعات، سه مرحله (blueprint/assembly/collapse) با فیزیک
- `src/face.ts` — بارگذاری صورت، یافتن نوک بینی و جابه‌جایی واقعی رأس‌ها برای ساخت سوراخ بینی
- `src/timeline.ts` — هماهنگی زمان‌بندی سه‌مرحله‌ای بین موتر و صورت با (GSAP)
- `src/ui.ts` + `index.html` + `src/style.css` — رابط فارسی راست‌به‌چپ

## دارایی‌ها (assets) و منشأ آن‌ها

محیط اجرای این پروژه به `polyhaven.com`، `sketchfab.com` و `poly.pizza` دسترسی
مستقیم نداشت، بنابراین به‌جای آن‌ها از دارایی‌های واقعی و باکیفیتی استفاده شد که
همان پروژه‌ی رسمی (Three.js) به‌صورت آزاد منتشر کرده (مجوز MIT/CC0، همگی
به‌صورت محلی در `public/assets` قرار دارند و هیچ درخواست شبکه‌ای در زمان اجرا
لازم ندارند):

|---|---|---|---|
| مدل موتر | `public/assets/models/car.glb` | نمونه‌ی رسمی (Three.js) — `examples/models/gltf/ferrari.glb` | مدل واقعی و چندقطعه‌ای (بدنه، شاسی/داخلی، شیشه، چهار تایر جدا) — دقیقاً همان چیزی که برای انیمیت‌کردن جداگانه‌ی قطعات لازم بود |

اگر می‌خواهید مدل‌های دیگری از (Sketchfab)/(Poly Pizza) یا (HDRI) دیگری از
(Poly Haven) جایگزین کنید، کافی است فایل `.glb`/`.hdr` را در همان مسیرها
جایگزین کنید؛ کد به‌صورت پویا اندازه/محل قطعات را از مدل می‌خواند (نه با
اعداد ثابت)، پس با مدل‌های دیگر هم کار می‌کند — به‌شرط آنکه مدل موتر شامل
گره‌هایی با نام‌های مشابه (`main`, `wheel_fl/fr/rl/rr`) یا مش‌های تفکیک‌پذیر
باشد؛ در غیر این صورت باید نگاشت قطعات در `src/car.ts` (توابع `buildPartGroups`)
را متناسب با مدل جدید تغییر دهید.

## یادداشت فنی: چرا مدل صورت بازپردازش شد؟

نسخه‌ی اصلی `facecap.glb` از (EXT_meshopt_compression) + (KHR_mesh_quantization)
+ ۵۲ (morph target) استفاده می‌کند. در نسخه‌ی (three.js) استفاده‌شده در این
پروژه، بارگذاری این مش خاص (mesh سر) با این ترکیب باعث می‌شد (GLTFLoader) تعداد
رأس‌ها را اشتباه محاسبه کند (هندسه‌ی به‌هم‌ریخته). با (gltf-transform)، مدل
(dequantize) شد، (morph targets) و انیمیشن‌های استفاده‌نشده حذف شدند، و چیدمان
رأس‌ها به‌صورت غیرتودرتو (`VertexLayout.SEPARATE`) بازنویسی شد — مشکل را کاملاً
برطرف کرد. اسکریپت بازپردازی در تاریخچه‌ی توسعه موجود است؛ در صورت نیاز به
بازتولید:

```bash
npx @gltf-transform/cli dequantize face.glb face-1.glb
# سپس با @gltf-transform/core به‌صورت برنامه‌ای:
#   - حذف morph targets هر primitive
#   - حذف انیمیشن‌ها
#   - نوشتن با NodeIO().setVertexLayout(VertexLayout.SEPARATE)
#   - doc.transform(prune())
```

## چطور برای ویدیو ضبط کنیم

1. `npm run dev` را اجرا کنید و صفحه را در مرورگر (ترجیحاً Chrome) در حالت
   تمام‌صفحه یا با یک پنجره‌ی بزرگ (مثلاً ۱۹۲۰×۱۰۸۰) باز کنید.
2. انیمیشن خودش پخش می‌شود (دکمه‌ی «توقف/پخش»، «از اول» و دکمه‌های «مرحله
   ۱/۲/۳» برای کنترل دستی در دسترس‌اند).
3. با هر ابزار ضبط صفحه (مثلاً (QuickTime Screen Recording) در مک،
   (OBS Studio) در ویندوز/لینوکس/مک، یا افزونه‌ی ضبط مرورگر) صفحه را ضبط کنید؛
   چون صحنه با ۶۰ فریم بر ثانیه و بدون نیاز به تعامل کاربر پخش می‌شود، فقط
   کافی است ضبط را از قبل از رسیدن به «مرحله ۱» شروع کنید تا کل داستان
   (سه مرحله + پایان) ضبط شود (حدود ۲۶ ثانیه برای یک چرخه‌ی کامل).
4. برای یک نمای سینمایی‌تر می‌توانید هنگام ضبط با ماوس (drag) کرده و زاویه‌ی
   دوربین را دستی تغییر دهید (کنترل خودکار دوربین با اولین تعامل کاربر موقتاً
   متوقف می‌شود و دوباره از سر گرفته می‌شود).

## نکات دسترس‌پذیری و کارایی

- طراحی راست‌به‌چین (`dir="rtl"`) با فونت (Vazirmatn) است؛ واژه‌های انگلیسی
  داخل پرانتز جدا شده‌اند تا چیدمان نشکند.
- `prefers-reduced-motion` رعایت می‌شود: در این حالت پخش خودکار انجام نمی‌شود
  و دوربین سینمایی خاموش است؛ کاربر با دکمه‌های مرحله/پخش صحنه را کنترل می‌کند.
- تمرکز کیبورد قابل‌دیدن است؛ کلیدهای میان‌بر: (Space) پخش/توقف، (1/2/3) رفتن
  به مرحله، (R) از اول.
